## Коммиты

* Формат: conventional commits — `feat:`, `fix:`, `chore:`, `refactor:`, `test:`, `docs:`, `style:`.
* Сообщение на английском, тело опционально.

# Описание проекта

* Базовая идея расписана в README.md и DESIGN-DOCUMENT.md
* Подробная документация по фичам лежит в docs/SPEC - данная спецификация должна быть актуальна и соответствовать нынешней реализации. 
* Если планируемые изменения в коде не соответствуют документам в docs/SPEC - предупредить пользователя, возможно спеку потребуется изменить.
* При появлении новых фичей необходимо записывать их в спецификацию. Новые документы помечать `- [ ]` и просить пользователя поревьюить. ДОкумент считается не проверенным, пока в нем не посечен `- [x]` как в остальных документах.
* Спецификация должна быть согласована и не противоречить сама себе. 

## Как писать код

* Код должен быть покрыт тестами максималльно. 
* Тесты должны проверять все сценарии, включая негативные, лучший вариант - табличный тест.
* Где невозможно сделать юнит тесты нужно делать e2e.
* Код должен следовать основным принципам программирования: SOLID, KISS - чтобы рефакторить в будующем было проще.

## Команды

* Сборка: `cargo build -p simpler-notes-mcp` (MCP сервер), `cargo build -p simpler-notes-core` (core)
* Тесты: `cargo test -p simpler-notes-core` (core, 145 тестов), `cargo test -p simpler-notes-mcp` (MCP, 59 тестов), `cargo test -p simpler-notes-mcp --test e2e` (e2e)
* Линтер: `cargo clippy` — должен быть чист, ноль предупреждений
* Никакого dead code. Неиспользуемые функции/переменные/импорты — удалять, не комментировать.
* Clippy warnings блокируют завершение задачи.
